# M3 MSI and INTx research — 2026-08-08

This note records the compatibility and lifecycle facts used to design A003.
It is a decision input, not runtime evidence.

## Locked platform facts

- The Yocto 6.0.2 lock selects Linux Yocto 6.18.24 for the qemux86-64 BSP.
  The modern PCI API allocates vectors with `pci_alloc_irq_vectors()` and
  resolves vector zero with `pci_irq_vector()`. The PCI core prefers MSI before
  INTx when both flags are present.
- The locked kernel's `pcim_enable_device()` integration manages later IRQ
  vector cleanup. Calling `pci_free_irq_vectors()` as well would double-release
  the vector, so this driver allocates before its managed IRQ request and relies
  on managed teardown.
- QEMU 10.2 EDU exposes one 64-bit MSI vector. It sends vector zero when MSI is
  enabled and otherwise asserts INTx. The device interrupt status must be
  acknowledged in both modes.

## Chosen contract

The module-load policy is `interrupt_mode=auto|msi|intx`, with `auto` as the
default. `auto` requests `PCI_IRQ_MSI | PCI_IRQ_INTX`; `msi` and `intx` request
only their named mode. The per-device read-only attribute reports the resolved
mode, never the policy value `auto`. INTx alone uses `IRQF_SHARED`.

The suite saves the endpoint's `msi_bus` value while default MSI is bound,
unloads the driver, writes zero, and reloads it. Automatic mode must then bind
through the PCI core's real INTx fallback, while required-MSI mode must leave
the device unbound. A `finally` path unloads transient modules, restores the
saved value while unbound, reloads default automatic mode, and proves MSI is
healthy. This is root-only test setup, not a driver interface or production
recommendation.

Rejected alternatives were a global `pci=nomsi` second boot, changing a bridge
and affecting child devices, a QEMU patch or unsupported device property, and a
synthetic writable driver fault switch. They either widen the test boundary,
increase maintenance, or test a private branch instead of PCI-core behavior.

## Compatibility and evidence

M3 changes the default interrupt behavior and adds a guest-visible attribute,
so it advances the development identity to `0.3.0-dev`, guest contract to 2,
runtime suite to 2, and runtime evidence to schema 2. The version-1 schema is
not edited, and the validator continues to consume historical M2 documents.

QEMU evidence does not qualify physical interrupt routing, electrical behavior,
or real hardware. DMA, MSI-X, multiple devices, and per-device user policy are
outside A003.
